# Работа через MCP и контроль качества

## Выполнение

- Актуальные инструкции `figma-use` и сопутствующих скиллов — источник правил вызова API. Этот файл не фиксирует устаревающие имена инструментов как обязательные.
- Если доступен `create_session`, создай сессию для нужного файла и передавай полученный sessionId во все поддерживающие его вызовы. Сохраняй вне файла ID страницы, экранов, ресурсов и всех созданных/изменённых узлов.
- Сначала инспектируй назначенную область и связанные ресурсы; используй поиск дизайн-системы и импорт по ключу, если они доступны. Для мастеров на другой странице переходи туда отдельным вызовом. Не сканируй чужие страницы и картинки целиком без необходимости.
- Между `use_figma`-вызовами состояние JavaScript и текущая страница могут сбрасываться. Передавай ID явно и устанавливай страницу через `await figma.setCurrentPageAsync(page)`. Соблюдай ограничения количества переключений из актуального figma-use.
- Связанные операции объединяй в разумные партии. Возвращай ID всех созданных и изменённых узлов, удалённые ID, границы и счётчики. Веди краткий реестр переиспользованных и созданных ресурсов.
- При ошибке учитывай `safeToRetryWithoutCanvasRead`. Если безопасный повтор не гарантирован, сначала проверь холст и выясни частичный результат. Не предполагаетcя ни автоматический откат всего вызова, ни сохранение всех изменений. Перед повтором ищи уже созданные ресурсы по ID/реестру, а не создавай дубли.

## Привязки

Однотонная заливка связывается с переменной через возвращаемую копию paint:

```js
const paints = node.fills.map(paint => ({ ...paint }));
paints[index] = figma.variables.setBoundVariableForPaint(
  paints[index], 'color', colorVariable
);
node.fills = paints;
```

Перед этим проверь, что `fills` — массив, выбранный paint имеет тип SOLID, а переменная имеет тип COLOR. Для strokes аналогично. RGB в Figma — 0…1; прозрачность однотонного paint задаётся отдельно. Не перезаписывай все заливки одной, если там нужны фото или градиент.

- Цвета стопов градиента и эффектов проверяй по актуальным типам API. Работай с копиями и сохраняй массив обратно; `setBoundVariableForEffect` тоже возвращает новое значение. На типы без поддержки привязок не распространяй неподдерживаемый вызов.
- Наличие стиля заливки не доказывает связь с переменной: проверяй фактические paint и `boundVariables`. У текста со смешанными цветами проверяй диапазоны через `getStyledTextSegments`.
- Текстовым слоям назначай стили через поддерживаемый async API; смешанным диапазонам — `setRangeTextStyleIdAsync`. Сначала загрузи текущие и целевые шрифты. Для уже существующего текста собери все начертания через `getStyledTextSegments(['fontName'])` и `await figma.loadFontAsync(...)`.
- Сверяй точные названия начертаний со списком доступных шрифтов, например `SemiBold` и `Semi Bold`. Не задавай `lineHeight` голым числом: используй поддерживаемый объект единиц.
- Текстовые свойства карточек делай TEXT-свойствами компонента; необязательные элементы — BOOLEAN, заменяемые иконки — INSTANCE_SWAP. Не прячь обязательный элемент только для исправления отступа. Варианты нужны для смысловых состояний, а не для каждого текста.
- Существующие инстансы не отсоединяй. Изменения внутренней структуры делай в разрешённом мастере; допустимые свойства и переопределения — в инстансе. Проверяй состояние с самым длинным реальным текстом и с выключенными опциональными элементами.

## Проверка перед сдачей

Проверяй созданные/изменённые экраны и нужные им мастера, а не весь файл. Область задавай явными ID.

| Что проверить | Условие готовности |
| --- | --- |
| Переиспользование | Нет нового семейства там, где подходит имеющееся; нет дублей стилей/переменных с той же ролью |
| Цвета | Управляемые цвета имеют реальные привязки; переменные существуют, режимы и алиасы разрешаются |
| Текст | Каждый слой/диапазон имеет стиль, фактические свойства соответствуют ему; локальные отличия обоснованы |
| Иконки и стрелки | Интерфейсные пиктограммы импортированы из SVG или переиспользуют векторные компоненты; внутри нет растровых подмен, текстовых стрелок, эмодзи или иконочного шрифта |
| Геометрия | Контейнеры и текст без необъяснимых дробей; поля, отступы, обводки и сетка согласованы |
| Слои | Временные узлы удалены; сохранённым скрытым элементам найдено назначение |
| Компоненты | Свойства работают, варианты не дублируются, изменения мастера не повредили другие использования |
| Визуальная проверка | Нет обрезания, наложений, случайных переносов цен/кнопок и смещённого центрирования |

### Автоматизированная помощь

Вставь содержимое `scripts/audit-layout.js` в `use_figma` и вызови:

```js
const page = await figma.getNodeByIdAsync('actual-page-id');
await figma.setCurrentPageAsync(page);
// Здесь определение auditLayout из scripts/audit-layout.js.
return await auditLayout(figma, ['actual-screen-id', 'actual-component-board-id']);
```

Подставь реальные ID, не запускай пример буквально. Функция только читает, включает сами корни, работает с перекрывающимися корнями без двойного подсчёта, проверяет привязки однотонных цветов, стопов градиента и обычных теней, текстовые диапазоны/стили, часть геометрии и кандидатов на очистку. Для скрытых и прозрачных узлов она возвращает кандидатов, **не решение удалить**.

Отчёт имеет `issues`, `review`, `coverage`, `counts`. Внимание:

- Пустой `issues` не означает, что аудит пройден: проверь также `coverage`, `review` и таблицу выше.
- Скрипт не доказывает неиспользуемость слоёв, не сравнивает компоненты по смыслу и не обходит все алиасы/режимы. Он также не определяет назначение изображений и текстовых символов: SVG-структуру и отсутствие растровых подмен в иконках проверь отдельно. Эти пункты не считаются автоматически пройденными.
- Статический аудит не проверяет переносы и реальную композицию; не поддерживаемые им типы эффектов и специальные текстовые узлы отмечаются в покрытии.
- Скрипт намеренно ничего не округляет, не перепривязывает и не удаляет. Исправляй только после проверки причины.

### Очистка и визуальная проверка

Сначала просмотри список кандидатов на удаление и зависимости. Удаляй доказанно ненужные узлы в назначенной области; неиспользуемость ресурса на одном экране не означает неиспользуемость в файле. Не раскрывай инстансы и маски ради сокращения дерева.

Сделай скриншот готового экрана или изменённых областей в достаточном масштабе. На длинной странице просматривай читаемые фрагменты. Проверяй контраст, иерархию, переносы, сетку, центрирование и свободное пространство. После визуальных правок проверь только затронутые места; повторять уже пройденные проверки без новых изменений не нужно.

Если шрифт заменён или текст стал выше, перемеряй связанные элементы и сдвинь нижние блоки, а не накрывай их увеличившимся текстом. Итоговый отчёт отделяет выполненное от исключений и неподтверждённых пунктов.

API-ссылки для проверки спорных полей: [переменные](https://developers.figma.com/docs/plugins/working-with-variables/), [Paint](https://developers.figma.com/docs/plugins/api/Paint/), [текстовые диапазоны](https://developers.figma.com/docs/plugins/api/properties/TextNode-getstyledtextsegments/). Фактическая поддержка в MCP может отличаться от полного Plugin API.

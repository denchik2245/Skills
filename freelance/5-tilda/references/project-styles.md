# Цвета и шрифты проекта

Цвета блоков ссылаются на стили проекта Tilda, а не записаны числом: поменял стиль в «Настройках сайта → Цвета» — поменялся весь сайт. Шрифты берутся из настроек проекта.

## Как это выглядит в JSON

| Что | Значение в Zero Block |
| --- | --- |
| Цвет из стиля | `var(--uc-color-color-<id стиля>,#hex)` — в `color`, `bgcolor`, `bordercolor`, `bgcolorhover`, `colorhover`, `ab_bgcolor` и в `<span style="color:…">` внутри текста |
| Шрифт заголовков проекта | `var(--t-headline-font,Arial)` |
| Шрифт текста проекта | `var(--t-text-font,Arial)` |

Так их записывает и сам редактор Tilda. Это не `typo_styleid`/`button_styleid` (стили типографики и кнопок), которые `zero_block_instructions` не велит добавлять. Тот же `var(--uc-color-color-…)` используй в CSS head-кода, если он есть.

## Порядок

1. **Палитра макета.** Сведи `palette` из всех `.d.json`: цвет, имена переменных Figma, сколько раз используется. Один стиль — одна роль: «Основной фон», «Заголовки», «Основной текст», «Золотой акцент», «Фон карточек». Имя стиля — последняя часть имени переменной Figma (`Brand/Золотой акцент` → «Золотой акцент»). Цвет без переменной, который встречается дважды и больше, тоже получает стиль. Разовые полупрозрачные цвета и градиенты остаются числами.
2. **Стили в проекте.** `get_project_settings` → `globalstyles_json`. Существующие стили с тем же цветом и ролью переиспользуй, не создавай дубли. Через MCP глобальные стили сейчас не создаются: у `update_project_settings` нет такого поля. Если в схеме инструмента оно появилось — используй его, иначе одним сообщением попроси пользователя добавить недостающие стили: «Настройки сайта → Цвета → Стили → Цвет», имя и hex списком. Затем снова прочитай настройки.
3. **Базовые цвета проекта.** `update_project_settings`: `headlinecolor`, `textcolor`, `linkcolor`, `bgcolor` = `var(--uc-color-color-<id>,#hex)` нужных стилей. В проекте с другими страницами — только с согласия пользователя.
4. **Шрифты.** Шрифт заголовков и текста — в настройки проекта (`save_project_fonts`, свои WOFF2 — через `upload_image`). `fonts.json` для конвертера: `{ "Tenor Sans": "var(--t-headline-font,Arial)", "Inter": "var(--t-text-font,Arial)" }`. Третий шрифт подключается отдельно в каждом блоке, где он нужен (см. `zero_block_instructions`, раздел 10).
5. **Сборка.** Сохрани ответ `get_project_settings` в `project-settings.json` и запускай конвертер с `--styles project-settings.json`. Он подставляет стиль сначала по имени переменной и цвету, потом только по цвету. Если подходят два стиля с одним цветом, в отчёте будет `STYLE_AMBIGUOUS`.
6. **Отчёт.** В `unboundColors` должны остаться только градиенты, полупрозрачные и разовые цвета. Если там сплошной цвет, который встречается часто, заведи для него стиль и пересобери блок.

## Проверка

- `get_zero_block` любого блока: `color` и `bgcolor` основных элементов начинаются с `var(--uc-color-color-`.
- На странице временно поменяй цвет одного стиля и посмотри, что изменились все блоки. Делай это только с согласия пользователя и сразу верни цвет. Если проверку не делал, просто сверь значения в JSON.
- В итоговом отчёте перечисли стили (имя и hex) и цвета, оставленные числами, с причиной.

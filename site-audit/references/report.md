# Структура клиентского отчета

## Сводка

Первая вкладка для владельца бизнеса содержит только строки 1–7: заголовок «Аудит сайта», сайт, дата аудита, целевая аудитория, целевое действие, объем проверки и главный вывод. Подписи расположены в A, значения — в B. Не добавляй блоки ниже строки 7 и отдельный лист с перечнем проверок.

В строке 6 кратко укажи проверенные страницы или типы страниц, основные сценарии, устройства/ширины и существенные ограничения. Непроверенные состояния, закрытый кабинет, реальное списание оплаты или недоступная аналитика не должны выглядеть проверенными.

В строке 7 сформулируй главный вывод по фактическим находкам; при необходимости сошлись на ID замечаний. Приоритеты остаются в реестре «Аудит», без отдельного подсчета на «Сводке».

## Аудит: 9 столбцов A–I

В шаблоне 30 строк с учетом шапки: фильтр A1:I30, выпадающие приоритеты B2:B30.

| Столбец | Содержание |
| --- | --- |
| A — ID | Стабильный `AUD-001`, `AUD-002`… Не меняется после сортировки. |
| B — Приоритет | P0, P1, P2 или P3. |
| C — Страница / URL | Прямая ссылка и место. Для системного дефекта — проверенные примеры и охват. |
| D — Устройство и состояние | Desktop / Mobile, фактическая ширина, существенные условия: браузер, раскрытие, ошибка ввода. |
| E — Проблема | Краткий заголовок и конкретный наблюдаемый факт. |
| F — Влияние на пользователя и бизнес | Какая задача затруднена и почему это важно. Непроверенное влияние помечай как предполагаемое. |
| G — Рекомендация | Исправление причины, пригодное для постановки задачи. |
| H — Как измерить эффект | Метрика, событие, юзабилити-проверка или сравнение до/после; необходимые данные. Для визуального дефекта достаточно повторной проверки. |
| I — Основание / принцип | Принцип и название заметки, при необходимости ссылка из sources.md. |

### Приоритет

- **P0:** подтвержденная блокировка главного сценария без рабочего обхода. Не использовать для вкусовых замечаний и неподтвержденных опасений.
- **P1:** существенный барьер в основном сценарии или отсутствие важной информации для решения. Приоритет не доказывает падение конверсии.
- **P2:** заметное замедление, лишние действия, неоднозначность или локальная проблема с обходом.
- **P3:** небольшая несогласованность или визуальная неточность с ограниченным влиянием.

Небольшие изменения с понятной пользой можно выделить в быстрые улучшения.

### Факты и гипотезы

В описании проблемы фиксируй воспроизведенное поведение и ограничения проверки. Влияние на бизнес помечай как предполагаемое, пока оно не измерено. Гипотезы о восприятии и эффективности сопровождай способом проверки: данные, интервью, тест или эксперимент. Отдельный столбец для этого не нужен.

### Учебный пример

Это пример записи, не результат аудита определенного сайта:

- Факт: «После ввода букв в телефон показано “Произошла ошибка”, поле не отмечено».
- Условия: Mobile, 390 px, обратный звонок, локальная проверка без отправки.
- Влияние: посетитель не понимает, что исправить; это может затруднять заявку.
- Рекомендация: показать понятную ошибку у телефона и сохранить остальные поля.
- Эффект: завершение формы в тесте; при наличии аналитики — ошибки телефона и доля завершений среди начавших форму.

## Оформление

Заголовки реестров — первая строка, без объединений и пустых строк между записями. Фильтр, закрепленная шапка и минимальное число идентифицирующих столбцов. У «Аудита» достаточно A–B. Темная сдержанная шапка со светлым текстом, светлое тело с темным текстом. Приоритеты различаются текстом, а не одним цветом.

Длинные описания шире ID и приоритетов; перенос и верхнее выравнивание. Высота вмещает текст. Не уменьшай шрифт ради числа столбцов. Добавь выпадающие значения для приоритета. Если используются цвета приоритетов, они реагируют на изменение значения.

На «Сводке» сохраняй видимую стандартную сетку Google Таблиц и тонкие серые границы ячеек A2:B7. Подписи полей выделяй светло-серым фоном, заголовок — полужирным. Связь подписи и значения должна читаться по строке.

Сводка читается отдельно от широкого реестра. Не добавляй искусственную оценку из 100: количество замечаний зависит от глубины обхода и не является мерой качества сайта.

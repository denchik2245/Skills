# Скилл: создание количественного опроса для продуктового исследования

Ты помогаешь продуктовым исследователям проектировать количественные опросы.
Результат — структурированный .docx-файл, готовый к переносу на платформу опросов (PathWay, SurveyMonkey, Typeform и др.).

## Шаг 1. Собери исходные данные

Перед тем как проектировать анкету, уточни у пользователя (если не указано явно):

1. **Цель исследования** — что именно хотим узнать? (одно предложение)
2. **Гипотезы** — какие предположения проверяем? (список, Г1, Г2…)
3. **Целевая аудитория** — кто отвечает? нужен ли скрининг?
4. **Платформа** — есть ли ограничения по типам вопросов или длине?
5. **Примерная длина** — сколько минут должен занимать опрос?

Если большинство из этого уже есть в контексте разговора — не переспрашивай, используй имеющееся.

## Шаг 2. Спроектируй структуру анкеты

### Обязательная архитектура

```
[Скрининг] — только если нужна фильтрация нецелевых респондентов
[Блок 1] — первая гипотеза / тема
[Блок 2] — вторая гипотеза / тема
...
[Демография] — должность, стаж, размер компании и т.д. — ВСЕГДА В КОНЦЕ
```

Если аудитория уже отфильтрована (например, пользователи конкретного продукта) — скрининг не нужен.

### Принципы расстановки вопросов

- **От общего к частному**: начни блок с оценочного вопроса («Как вы оцениваете...»), потом уточняй («Какие именно...», «Как часто...»)
- **Ветвления** — применяй экономно, только когда вопрос реально нерелевантен части аудитории
- **Демография** — в конце, после содержательных вопросов: так выше конверсия и меньше отказов
- **Длина** — ориентируйся на 7–10 минут прохождения (≈15–20 вопросов)

## Шаг 3. Сформулируй вопросы

### Типы вопросов и когда их использовать

| Тип | Когда | Обозначение в тексте |
|-----|-------|----------------------|
| Один вариант (radio) | Взаимоисключающие варианты | `◯ Вариант` |
| Несколько вариантов (checkbox) | Можно выбрать несколько | `☐ Вариант` |
| Шкала Ликерта (5 пунктов) | Степень согласия, важности, удовлетворённости | `◯ 1 — … ◯ 5 — …` |
| Открытый | Когда нужны нюансы, которые не предугадать | Поле `_____________` |

Вариант «Другое: _____________» добавляй почти везде — чтобы не терять нестандартные ответы.

### Технические пометки для платформы

Пиши прямо в скобках после текста вопроса:
- `(можно выбрать несколько)`
- `(включить перемешивание вариантов)`
- `(обязательный вопрос)`
- `(скриншот: вставить изображение X)`

### Ветвления

Показывай стрелкой прямо в документе:
```
→ Если «Да» — перейти к В3
→ Если «Нет» — перейти к В5
```

## Шаг 4. Проверь вопросы по когнитивной модели Рогозина

Перед финализацией каждый вопрос мысленно проходит 4 стадии:

1. **Понимание** — формулировка однозначна? Нет двойных вопросов в одном? Нет жаргона?
2. **Извлечение из памяти** — респондент реально может это вспомнить? Не просим сравнивать то, что сложно удержать в голове одновременно?
3. **Суждение** — нет ли социально желательного ответа, который «напрашивается»? Нейтральна ли формулировка?
4. **Форматирование ответа** — шкала симметрична? Варианты исчерпывают возможные ответы? Нет ли дублей?

Типичные ошибки, которые нужно исправить:
- Двойной вопрос: «Насколько удобен и понятен интерфейс?» → разделить на два
- Ведущий вопрос: «Согласны ли вы, что функция полезна?» → переформулировать нейтрально
- Асимметричная шкала: «Плохо / Нормально / Хорошо / Отлично» → сделать симметричной
- Социально нежелательный вариант ответа: убрать формулировки вроде «Мы работаем кое-как»

## Шаг 5. Составь приложение с логикой ветвлений

В конце документа добавь таблицу:

| Вопрос | Условие | Следующий вопрос |
|--------|---------|------------------|
| В1.2 | «Да» | В1.3 |
| В1.2 | «Нет» | → Перейти к блоку 2 |

Это нужно тому, кто будет переносить анкету на платформу.

## Шаг 6. Сохрани как .docx

Используй инструкции из скилла `docx` для создания файла. Структура документа:

```
Цель исследования
Гипотезы
─────────────────
АНКЕТА
  Скрининг (если нужен)
  Блок 1: [тема]
  Блок 2: [тема]
  ...
  Демография
─────────────────
Приложение: логика ветвлений
```

Сохрани в папку пользователя с именем `Анкета_[тема]_v1.docx`.

## Примеры хороших и плохих вопросов

**Плохо:** «Используете ли вы наш сервис часто и доверяете ли ему?»
→ Двойной вопрос. Разбить на два отдельных.

**Хорошо:** «Как часто вы используете сервис?» + «Насколько вы доверяете данным из сервиса?»

---

**Плохо:** «Согласны ли вы, что уведомления о новых функциях важны?»
→ Ведущий вопрос. Ответ «Да» социально навязан.

**Хорошо:** «Насколько важны для вас уведомления о новых функциях? ◯ Очень важно ◯ Скорее важно ◯ Нейтрально ◯ Скорее не важно ◯ Совсем не важно»

---

**Плохо (шкала):** «◯ Плохо ◯ Нормально ◯ Хорошо ◯ Отлично»
→ Асимметрично: 3 позитивных варианта, 1 негативный.

**Хорошо:** «◯ Очень плохо ◯ Скорее плохо ◯ Нейтрально ◯ Скорее хорошо ◯ Очень хорошо»

# Техника HTML

Каждый экран — это картинка, собранная из HTML. Он должен одинаково выглядеть на PNG из Playwright и в просмотрщике (iframe, уменьшенный под экран).

## Файлы

- `<dir>/desktop.html` и `<dir>/mobile.html` — по одному файлу, стили в `<style>`, JavaScript не нужен.
- Начинай с `templates/desktop.html` (ширина 1920, контейнер 1200) и `templates/mobile.html` (ширина 375, поля 20). Переменные цвета и шрифта в обоих одинаковые — копируй `:root` из десктопа.
- Только px. Без `vw`, `vh`, `%` для размеров экрана, `clamp()`, медиазапросов: холст фиксированный.
- Десктоп: `html, body { width: 1920px }`, первый экран `min-height: 1080px`. Мобильная: `html, body { width: 375px }`, первый экран 812, дальше по содержимому.
- Мобильная рендерится в 2×, поэтому картинки для неё — шириной 750–800.

## Метки пояснений

- Элементу desktop.html, к которому относится пояснение, добавь атрибут `data-note="1"` (номер = `id` в `meta.json`).
- Метка встаёт рядом с элементом слева, по центру его высоты, подсветка — по его рамке. Вешай атрибут на сам элемент (кнопку, цену, блок цифр), а не на большую обёртку.
- Если слева нет места (элемент вплотную к другому, как цена рядом с кнопкой), задай пояснению в `meta.json` `"side": "right"`, `"top"` или `"bottom"`. Метка не должна закрывать текст — проверь на странице проекта.
- Один элемент — одно пояснение. `build.mjs` предупредит о метках без пояснений и пояснениях без меток.

## Сетка и числа

- Контент 1200 по центру (x 360–1560), 12 колонок 78 + гаттер 24: 6 кол. = 588, 8 = 792.
- Тексты и кнопки — внутри 1200. За колонку выходят только фото, подложки и декор.
- Кегли и интерлиньяжи кратны 4, отступы кратны 8, скругления: кнопки 12, карточки 24, подложки 32–40. Шкала — `layout-system.md` figma-landing.

## Шрифты

- Google Fonts через `<link>` с `display=swap`. Шрифт — с цветового референса или ближайший на Google Fonts **с кириллицей** (проверь `subset=cyrillic` на странице шрифта).
- Не использовать Unbounded и Manrope.
- Все начертания, которые используешь, перечисли в ссылке (`wght@400;500;700`) — иначе браузер подделает жирный.

## Картинки

Приоритет:

1. фото и логотип заказчика из присланных материалов или с его сайта;
2. бесплатные стоки с лицензией на коммерческое использование (Unsplash, Pexels): скачай в `assets/`, источник запиши в итог;
3. генерация (`generate_image` Figma MCP) — тратит кредиты, только если пользователь разрешил;
4. без фото: композиция из формы, цвета, иконок, типографики.

- Только локальные файлы `assets/*.jpg|png|webp|svg`, никаких горячих ссылок на чужие сайты.
- Ширина файла не больше 2× от показанной, вес до ~500 КБ. Сжать на Mac: `sips -Z 2400 -s format jpeg -s formatOptions 80 in.jpg --out assets/hero.jpg`.
- Фото под текстом — с градиентом или подложкой, чтобы текст читался.
- Логотип заказчика без SVG — словесный знак текстом, не размытая картинка.

## Иконки и декор

- Иконки — инлайн SVG 24×24, stroke 2 (в стиле Lucide), цвет через `currentColor`.
- Наклон фото — целые градусы −6…+6 (`transform: rotate(-4deg)`), тени мягкие, с цветом от фона.

## Что ломает рендер

- Анимации появления (`opacity: 0` + `@keyframes`) — на скриншоте элемент пропадёт. Не используй анимации.
- `position: fixed` — в iframe и на скриншоте всей страницы ведёт себя иначе. Шапку делай обычной.
- Внешние скрипты, виджеты, карты, `iframe` — не грузятся или грузятся по-разному. Карту рисуй заглушкой.
- `backdrop-filter` поверх фото работает, но проверь на скриншоте.
- Шрифт без кириллицы — текст молча упадёт в системный; `build.mjs` предупредит.

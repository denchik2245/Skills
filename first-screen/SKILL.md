# Первый экран для отклика

Цель — заказчик открывает ссылку и за 5 секунд видит: дизайнер уже понял мой бизнес, и вот как может выглядеть мой сайт. Поэтому в каждом варианте — его название, его услуги, его город и цены из ТЗ, а не абстрактный шаблон.

## Источники

- [правила первого экрана](references/hero-rules.md) — состав экрана, направления вариантов, тексты, тест 5 секунд;
- [техника HTML](references/html-rules.md) — сетка, шрифты, картинки, что ломает рендер;
- `templates/variant.html` — заготовка варианта;
- из `../figma-landing/references/`: `knowledge-base.md` (конверсия, продающий текст, типографика), `layout-system.md` (сетка 1200, шкала, цвет), `selling-check.md` (тест 5 секунд), блок Hero в `block-patterns.md`.

Прочитай оба файла своих references и перечисленные файлы figma-landing перед первым вариантом.

## Скрипты

Все в `scripts/`, запускай из папки скилла (`node scripts/…`). Пути и автор — в `config.json`.

| Скрипт | Что делает |
| --- | --- |
| `new.mjs "Название" [--domain site.ru]` | создаёт папку проекта на витрине, печатает `slug` и `dir` |
| `build.mjs <slug> [--only b]` | неразрывные пробелы, PNG+JPG каждого варианта, `og.jpg`, страница просмотрщика; печатает высоты и предупреждения |
| `publish.mjs <slug>` | коммит и push, ждёт GitHub Pages, проверяет, что ссылка открывается |
| `setup.mjs` | один раз: создаёт публичный репозиторий и включает Pages |

Если `build.mjs` пишет, что нет playwright: `npm install && npx playwright install chromium` в папке скилла.

## 1. Вход

Нужно ТЗ: что за бизнес и что заказчик хочет. Всё остальное не блокирует:

- референсы — если роль не указана, определи сам (цвет и шрифт / композиция / настроение фото) и назови;
- материалы заказчика — логотип, фото, текущий сайт: бери оттуда название, услуги, цены, контакты;
- число вариантов — по умолчанию 3; 2, если ТЗ узкое или пользователь просит быстрее.

Если ТЗ — ссылка на заказ, прочитай страницу. Спрашивай только когда непонятно, что продаёт заказчик.

## 2. Разбор

Внутренне: оффер, кому, целевое действие, факты из ТЗ (цифры, цены, гео, сроки), палитра и шрифт, чего нет и станет заглушкой.

Покажи пользователю коротко — по строке на вариант: буква, название направления, композиция, угол H1. Начинай вёрстку, не дожидаясь ответа, если он не просил согласовать.

## 3. Проект и картинки

1. `node scripts/new.mjs "<Бренд или ниша>" --domain <домен заказчика, если есть>`.
2. Впиши в `meta.json` варианты: `{"id": "a", "name": "1–3 слова", "about": "одно предложение для заказчика: идея варианта и для кого"}`. `description` — одна фраза для превью ссылки.
3. Картинки — в `<dir>/assets/` по приоритету из html-rules.md. Всё, что скачано со стоков или сгенерировано, перечисли в итоге.

## 4. Вёрстка

Каждый вариант — `<dir>/a.html`, `b.html`, `c.html` на основе `templates/variant.html` по правилам html-rules.md и hero-rules.md. Варианты должны отличаться композицией и подачей, а не перекраской.

## 5. Сборка и самопроверка

1. `node scripts/build.mjs <slug>`; исправь всё из `warnings`.
2. Открой каждый `<id>.jpg` через Read и проверь глазами:
   - висячие предлоги и одиночные слова в конце строк, перенос в кнопках и ценах;
   - обрезанный, наехавший или нечитаемый на фото текст;
   - пустоты, перекосы сетки, элементы за колонкой 1200 (кроме фото и декора);
   - тест 5 секунд из hero-rules.md.
3. Правь и пересобирай точечно: `build.mjs <slug> --only b`. Обычно хватает 1–2 кругов.

Готовое можно показать пользователю до публикации: локальный просмотрщик — `<dir>/index.html` (путь печатает build).

## 6. Публикация

- Первый раз, если у папки витрины нет `origin`: `setup.mjs` создаёт **публичный** репозиторий из `config.json`. Перед запуском спроси пользователя.
- `node scripts/publish.mjs <slug>` — дождись `"live": true`.

Не клади в проект то, что заказчик не готов показывать всем: репозиторий публичный, ссылку нельзя угадать, но она не секретная.

## 7. Итог

Сообщи:

- ссылку на проект и ссылки на каждый вариант (`…/#b`);
- пути к JPG для вложения в отклик (`attach` из publish);
- по варианту: идея в одной строке и результат теста 5 секунд;
- **заглушки** — всё, чего не было в ТЗ (цифры, рейтинг, цены, фото со стока);
- что текст отклика с этой ссылкой может написать `freelance-response`.

## Правки и управление

- Правка варианта: меняй HTML → `build.mjs <slug> --only <id>` → `publish.mjs <slug>`. Ссылка не меняется.
- Новый вариант к готовому проекту: следующий файл (`d.html`) + запись в `meta.json`.
- Удалить проект: только по просьбе пользователя — удалить папку `<siteDir>/<slug>` и `publish.mjs` любого проекта (или `git rm` + push).
- Список проектов: папки в `siteDir` с `meta.json`.
